# Note Systems bot

Бот для тестнета [note.systems](https://note.systems/) (Robinhood Chain testnet, chain id 46630).
Для каждого аккаунта: кран → контроль стрика → депозиты COUPON → SHIELD → облигации → вход на сайт и ник.
Отдельный скрипт `Boost.py` раздаёт газ по массе аккаунтов, забирает кран и сливает токены на основные кошельки.

> Все действия в блокчейне идут напрямую через RPC (провайдер прокси блокирует RPC‑хост).
> Прокси используются только для запросов к сайту note.systems (вход и ник).

---

## 1. Установка

Нужен Python 3.11+.

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Linux / macOS
pip install -r requirements.txt
```

## 2. Файлы с данными

В репозитории есть только примеры. Скопируйте их и заполните своими данными:

| Пример | Рабочий файл | Для чего |
|---|---|---|
| `accounts.example.txt` | `accounts.txt` | основные аккаунты для `main.py` |
| `Proxy.example.txt` | `Proxy.txt` | запасные прокси |
| `Boost.example.txt` | `Boost.txt` | массовые аккаунты для `Boost.py` |

```bash
copy accounts.example.txt accounts.txt
copy Proxy.example.txt Proxy.txt
copy Boost.example.txt Boost.txt
```

Рабочие `.txt` файлы в git не попадают: так настроен `.gitignore`. Сиды и прокси остаются только у вас на диске.

### accounts.txt

Один аккаунт на строку: `сид фраза,прокси[,ник]`

```
word1 word2 ... word12,user:password@host:port
word1 word2 ... word12,user:password@host:port,MyNick
```

- **Сид фраза**: 12 или 24 слова через пробел. Адрес кошелька вычисляется из неё по стандартному пути `m/44'/60'/0'/0/0`, как первый аккаунт в MetaMask.
- **Прокси**: `user:password@host:port`, можно с `http://` в начале.
- **Ник**: необязателен. Если его нет, бот придумает ник сам и допишет третьим полем (при `NICK = 1`). Сайт разрешает ставить ник только после первого депозита.
- Первый аккаунт в файле — источник ETH для `fund.py`.

### Proxy.txt

Одна прокси на строку: `user:password@host:port`.
Это запас: когда прокси аккаунта умирает или её IP блокируют, бот берёт первую строку отсюда, **удаляет её из Proxy.txt** и записывает аккаунту. Одна прокси никогда не достаётся двум аккаунтам.
Заменённая прокси не пропадает: она дописывается в `Proxy_dead.txt`.

**Защита от сбоя провайдера.** Если 5 прокси подряд не работают и ни одна между ними не сработала, бот считает, что упал провайдер прокси или интернет, а не сами прокси. Он перестаёт брать новые прокси из `Proxy.txt` и пропускает вход на сайт до конца запуска; ончейн-шаги продолжаются. Чтобы понять причину, он открывает сайт через первую запасную прокси из `Proxy.txt` (она остаётся в файле; напрямую с вашего IP бот к сайту не ходит). В логе будет `!! proxies stopped: ...` с причиной: сайт отказывает (`HTTP 403` и т.п.), упал провайдер или сеть, либо плохи сами прокси аккаунтов. Каждую прокси перед заменой бот проверяет дважды, с паузой 5 с.

### Boost.txt

Как accounts.txt, но без ника: `сид фраза,прокси`. Можно писать **одну сид фразу без прокси**:

```
word1 word2 ... word12,user:password@host:port
word1 word2 ... word12
```

Аккаунт без прокси получит её из `Proxy.txt` на шаге входа (LOGIN), и она сразу запишется в его строку.
Если LOGIN выключен, прокси не расходуются.

## 3. main.py: основные аккаунты

```bash
python main.py        # все аккаунты из accounts.txt
python main.py 5      # только аккаунт из 5-й строки
```

Порядок шагов для каждого аккаунта:

**FAUCET → STREAK_GUARD → DEPOSIT → SHIELD → BONDS → DESK → STAKE → LOCK → VOTE → BUYBACK → SETTLE → OMNICHAIN → VAULT → CREDIT → BUILDER → SWAP → PROPOSALS → LOGIN/NICK**

> С 1 октября 2026 бот работает с **финальной тестнет-сборкой** (pre-season): новый NoteCore `0x55eA…`, новые USDG и акции,
> новый BondDepository. Season 0 закрыт и заморожен, старые контракты очков больше не дают.
> Журналы новой сборки: `deposits_v2.txt`, `shields_v2.txt`, `micro_v2.txt`, `legs_v2.txt` (старые `deposits.txt` и т.п. относятся к Season 0).

Модули включаются в `config.py` (`1` включён, `0` выключен):

| Модуль | Что делает |
|---|---|
| `FAUCET` | забирает кран: 1 000 USDG + 10 каждой акции (раз в 24 ч) |
| `STREAK_GUARD` | проверяет здоровье позиций и спасает стрик после пробоя (см. ниже). Нужен только для Season 0 (стрик и Salvage Window из замороженного профиля), по умолчанию выключен |
| `DEPOSIT` | делает `DEPOSIT_COUNT` депозитов COUPON в случайные открытые серии, каждый на `DEPOSIT_PCT` % баланса USDG |
| `SHIELD` | ставит все акции в SHIELD, размер подгоняется так, чтобы позиция полностью сматчилась; плюс пары COUPON+SHIELD из своих средств |
| `BONDS` | забирает созревшие NOTE из облигаций и покупает одну облигацию за USDG на `BOND_USDG` (поток Bonds + квест; если рынок почти заполнен, покупает сколько влезает). NOTE созревают 24 ч и идут в модули ниже |
| `DESK` | кладёт `DESK_PCT` % USDG в Desk. Никогда не выводит: запрос на вывод в первые 7 дней сжигает неделю |
| `STAKE` | стейкает `STAKE_PCT` % NOTE в sNOTE. Cooldown не запускает: он сжигает неделю |
| `LOCK` | блокирует `LOCK_PCT` % NOTE в veNOTE на `LOCK_DAYS` дней (дальше докладывает в тот же лок) |
| `VOTE` | отдаёт всю силу veNOTE за один гейдж, повторяет раз в 10 дней |
| `BUYBACK` | продаёт немного NOTE в аукцион выкупа; пропускается, пока в аукционе нет USDG |
| `SETTLE` | рассчитывает позиции в сериях, которые прошли страйк (Live): `NoteCore.settle` выпускает ноги COUPON/SHIELD и возвращает несматченную часть USDG. Без этого `OMNICHAIN` нечего отправлять |
| `OMNICHAIN` | отправляет `OMNICHAIN_PCT` % одной ноги COUPON (только серии Live) в Arbitrum Sepolia, комиссия LayerZero ~0.0002 ETH. Обратно не возвращает |
| `VAULT` | кладёт `VAULT_PCT` % USDG в Build-хранилище (ERC-4626) фабрики `0x9bAb…`: первый раз в случайное хранилище с активами, дальше докладывает в то же. Никогда не выводит. Журнал: `vaults_v2.txt` |
| `CREDIT` | приложение Credit (рынки Morpho `0x44f0…` на ногах COUPON, LLTV 38,5%). Кнопок на сайте пока нет, бот работает с контрактами напрямую. Каждый запуск даёт в долг `CREDIT_SUPPLY_PCT` % USDG в рынок (дальше в тот же). Один раз на кошелёк: оборачивает `CREDIT_WRAP_PCT` % одной ноги COUPON в токен `nCm…` (`LegWrapFactory 0x6E94…`, 1:1), вносит его залогом и занимает `CREDIT_BORROW_PCT` % от допустимого (LTV ~6–13%, ликвидация при 38,5%). Займ не гасит, ничего не выводит. Поток Credit 7% (supply × дни 0,6 + долг × дни 0,4) + квест. Журнал: `credit_v2.txt` |
| `BUILDER` | квест Builder (×3): один раз на кошелёк разворачивает своё USDG-хранилище через фабрику `0x9bAb…` (владелец = кошелёк, своё имя и настройки). Байткод берётся из готовой транзакции и сверяется с `vaultCodeHash` фабрики. Журнал: `built_v2.txt` |
| `SWAP` | приложение Swap (`swap.py`, поток 8% + 7 квестов): 1–3 свапа за запуск (в основном покупки за USDG, первыми идут акции, которыми кошелёк ещё не торговал; продажа акций с крана, а если движку не хватает USDG (`CapitalLimit`) — покупка вместо неё), докладывает часть одной акции в её Regular/Continuous-хранилище, USDG в Senior-хранилище и один раз на кошелёк делает депозит в Backstop (рассчитывается при следующих запусках, когда у всех рынков свежие цены). Ничего не выводит. Цены — подписанные отчёты Chainlink с сервиса сайта (напрямую, в запросе только ID фидов). Рынки: `swap_markets.json` (195 штук, скопированы из кода сайта). Журнал: `swap_v2.txt` |
| `PROPOSALS` | голосует по открытым предложениям NoteGovernor и UpgradeGovernor силой veNOTE (её даёт `LOCK`), по каждому один раз. Очков не даёт (поток votes — только голоса за гейджи), поэтому выключен |
| `LOGIN` | входит на note.systems/community через прокси аккаунта и выводит очки, ранг и стрик |
| `NICK` | ставит ник, если его ещё нет |

Прочие настройки `config.py`:

| Параметр | Значение |
|---|---|
| `DEPOSIT_COUNT` | сколько новых депозитов за запуск на аккаунт |
| `DEPOSIT_PCT` | размер одного депозита, % от баланса USDG (случайно в диапазоне) |
| `BOND_USDG` | сумма покупки облигации в USDG |
| `SWAP_*` | Swap: число свапов, USDG на покупку, шанс и % продажи, допуск по цене, % акции в хранилище, % USDG в Senior, сумма депозита в Backstop |
| `CAPTCHA_SERVICE` | сервис капчи (`capsolver`, `2captcha` или `anticaptcha`) для LOGIN/NICK и Boost (см. ниже). Ключ сервиса лежит в `captcha_key.txt` (пример: `captcha_key.example.txt`), в git не попадает |
| `THREADS` | сколько аккаунтов обрабатывается параллельно |
| `DELAY_BETWEEN_ACCOUNTS` | пауза после аккаунта, секунды |
| `DELAY_BETWEEN_TX` | пауза между транзакциями, секунды |

**Капча при входе.** Перед note.systems стоит проверка LiteSpeed «Bot Verification» (невидимая reCAPTCHA v2,
страница 403 вместо ответа). Бот замечает её на любом запросе входа, решает через `CAPTCHA_SERVICE` (`captcha.py`,
напрямую, без прокси), отправляет токен на `/.lsrecap/recaptcha` через прокси аккаунта и повторяет запрос: сайт
после этого пропускает IP прокси какое-то время, cookie не нужна. Нет баланса или неверный ключ: вход
останавливается до конца запуска (`captcha service stopped`), остальные модули работают дальше.

### STREAK_GUARD: контроль стрика

Стрик на странице Community растёт на 1 за каждое наблюдение, при котором нота осталась выше барьера. Пробой барьера или ранний выход сбрасывает стрик. Если нота пробила барьер, есть **48 часов**, чтобы зайти заново на ту же сумму или больше. Тогда сохраняется 50 % стрика, а новая нота первую неделю даёт двойные очки (Salvage Window).

Что делает модуль при каждом запуске `main.py`:

1. Находит все позиции кошелька по событиям контракта, включая сделанные вручную через сайт.
2. Считает запас до барьера так же, как страница Portfolio: **Sound** ≥ 20 %, **Watch** 10–20 %, **At risk** < 10 %, **Breached** ниже барьера. В логе будет строка `!! AT RISK ...` для каждой ноты в зоне риска.
3. Если нота пробила барьер и 48 часов ещё не прошли, заходит в новую открытую серию **той же акции и той же стороны** (COUPON или SHIELD) на ту же сумму, округлённую вверх.
4. Если такой депозит уже есть (сделан ботом, `main.py` или вручную), повторно не заходит.

Модуль стоит сразу после крана, чтобы на перезаход хватило USDG до того, как их потратят DEPOSIT, SHIELD и BONDS.
**Запускайте `main.py` хотя бы раз в сутки**, иначе 48 часов на перезаход могут пройти между запусками.
Если на кошельке меньше USDG, чем стояло в пробитой ноте, в логе будет `re-entry FAILED: not enough USDG`.

## 4. Boost.py: массовые аккаунты

```bash
python Boost.py
```

Настройки вверху файла `Boost.py`:

| Параметр | Что делает |
|---|---|
| `SEND_ETH` | делит ETH первого аккаунта Boost между остальными (через «хабы», параллельно) |
| `LOGIN` | вход на сайт через прокси аккаунта (2 запроса); нет прокси → берётся из Proxy.txt |
| `FAUCET` | забирает кран |
| `SEND_TOKENS` | отправляет все USDG и акции на кошельки из `accounts.txt` (аккаунты Boost делятся на равные группы, одна группа на кошелёк) |
| `THREADS` | параллельных аккаунтов |
| `HUBS` | сколько хабов рассылают ETH |
| `ETH_RESERVE` | сколько ETH оставить на первом аккаунте |

Адреса получателей для `SEND_TOKENS` вычисляются из сид фраз `accounts.txt`.
При старте Boost.py вычисляет адреса всех аккаунтов из сидов параллельно на всех ядрах, для ~9 000 аккаунтов это около 25 секунд.

## 4a. micro.py: микро-депозиты USDG

```bash
python micro.py              # все аккаунты из accounts.txt
python micro.py -t 20        # 20 аккаунтов параллельно
python micro.py -t 20 -n 100 # 20 потоков, по 100 депозитов на аккаунт
python micro.py 5            # только аккаунт из 5-й строки
```

Без `-t` и `-n` берутся `THREADS` и `COUNT` вверху файла.

Отдельно от `main.py`. На каждый аккаунт делает `COUNT` депозитов COUPON по `AMOUNT` USDG (минимум контракта 10 USDG) в случайные открытые серии.
Один approve на весь запуск, транзакции уходят пачками по `BATCH` штук без ожидания каждой. Журнал: `micro.txt`.
Один депозит стоит примерно 0.0000013 ETH газа, 300 депозитов около 0.0004 ETH. Когда ETH не хватает, аккаунт останавливается с `no ETH for gas`.
Настройки вверху файла `micro.py`.

## 5. fund.py: газ для основных аккаунтов

```bash
python fund.py          # по 0.01 ETH
python fund.py 0.02     # своя сумма
```

Отправляет ETH с первого аккаунта `accounts.txt` на остальные. Кошельки, где уже есть хотя бы половина суммы, пропускаются.

## 6. Служебные файлы (создаются сами)

| Файл | Что хранит |
|---|---|
| `deposits_v2.txt`, `shields_v2.txt` | журнал депозитов COUPON / SHIELD (чтобы не заходить дважды в одну серию) |
| `legs_v2.txt` | ноги, уже отправленные в Arbitrum Sepolia (каждая один раз) |
| `vaults_v2.txt` | депозиты в хранилища: какое хранилище выбрал кошелёк |
| `credit_v2.txt` | Credit: `адрес,серия,действие,сумма,tx` (supply / wrap / collateral / borrow) |
| `built_v2.txt` | Builder: какое хранилище развернул кошелёк |
| `swap_v2.txt` | Swap: `адрес,вид,тикер,сумма,детали,tx` (buy / sell / regular / continuous / senior / backstop-request / backstop-settle) |
| `registered.txt` | аккаунты, которые уже входили на сайт |
| `Proxy_dead.txt` | прокси, которые бот заменил (после сбоя их можно вернуть в `Proxy.txt`) |
| `boost_done.txt`, `boost_funded.txt`, `boost_hubs.txt` | прогресс Boost.py |

Их не нужно создавать и нельзя удалять посреди работы: по ним бот понимает, что уже сделано.
